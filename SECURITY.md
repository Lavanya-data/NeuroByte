# Security and privacy status (read before any real use)

**This is a hackathon prototype. It is NOT production-grade authentication or clinical storage.**

| Area | Current state | Needed for production |
|---|---|---|
| Local accounts | Password hashed with salted PBKDF2 (150k iterations) and stored in browser localStorage. The saved records on this device are encrypted (AES-GCM, key derived from the password with PBKDF2; the key is never stored). If the browser has no Web Crypto, the records fall back to plain storage. Records from older versions are read once and then re-saved encrypted. With a wrong password the encrypted copy is left untouched (kept as `mx_undec_...`). 5 failed logins lock the form for 30 s, but this is client-side only. | Server-side auth, server-side rate limiting, key recovery design |
| Demo account | Checked against an unsalted SHA-256 hash embedded in the page source. Fine for a demo, weak against offline guessing. | Remove before real use |
| Online accounts (Supabase) | Passwords handled by Supabase Auth. Access and refresh tokens are kept in memory only (not persisted). Row-level security in `supabase.sql` limits each user to their own row, including delete, and each row is size-limited. Records are stored as one unencrypted JSON row. A failed save shows a warning and is retried automatically (every 30 s and when the connection returns). At sign-in the newer of the device copy and the online copy is used and the other is kept as a backup on the device (`mx_bak_...`). Tested against a mocked Supabase only, not a live project. | Field-level encryption, audit log, tested policies, record-level merge |
| Sessions | Auto sign-out after 15 minutes without a click, key press, scroll or touch. Signing out (or timing out) saves, then clears the data from memory and from the screen. Online sessions use the refresh token to renew the access token before it expires. If it cannot be renewed the user is told to sign in again and nothing is lost (it stays saved on the device). | Server-side revocation |
| Deletion | "Reset my data" deletes the local copy and the Supabase row. Backups and Gemini-side logs are outside our control. | Verified erasure workflow |
| `/api/*` functions | Only the Medoryx page can call them (custom header + same-site Origin check). Per-IP limits per minute: ask 30, translate 30, explain 15, extract 8, health 3. Limits live in the memory of each serverless instance, so they are best-effort; for a hard limit add a Vercel Firewall rate-limit rule. Optional: set `REQUIRE_AUTH=1` with `SUPABASE_URL` and `SUPABASE_ANON_KEY` to accept only signed-in users (leave it off while judges use the offline demo account). A determined attacker who copies the header is not stopped by the header check alone. | Mandatory auth, WAF, per-user quotas |
| External AI | Uploaded documents, lab values and questions go to Google Gemini via our `/api/*` functions. The app asks for consent first, **per account on a browser**, and blocks AI calls and page translation until given. Use a paid Gemini key: free-tier data may be used by Google to improve its products (check Google's current terms). The translation feature sends visible page text, which can include diagnosis text and the user's name, so it is also gated by that consent. | Data-processing agreement, redaction before sending, regional hosting review |
| Original documents | While you review an upload, the original (PDF, photo or the text you pasted) is shown next to the extracted values so you can compare. A PDF is shown from the browser's own memory and is released when you save, cancel or sign out. Photos under 1.2 MB are stored with the record; PDFs and pasted text are not preserved. | Encrypted object storage |
| Emergency contacts | Up to 8 contacts (name, phone number, relationship) are saved with the rest of the records, so they are encrypted on the device and synced online like the other data, and are cleared on sign-out and by Reset my data. Phone numbers are checked before saving. The Call and Text buttons only open the phone's own dialer or messaging app; Medoryx cannot call or alert anyone itself. "Text my location" reads the location only when tapped and puts it only in the text message the user sends; it is not stored or sent to Medoryx. The helpline list (112, 108, 102, 104, 14416 / 1800-891-4416, 1098, 181, 14567) was checked against Government of India sources in October 2026; 102, 104 and 108 differ by state. | Re-check the list every few months; state-specific helplines; alerting contacts automatically |
| ABDM | The ABHA link is a mock (not verified). | NHA sandbox credentials and certification |

**Data from files and servers is never trusted:** everything loaded from this device, the online copy or an imported FHIR file is re-checked (types, lengths, real dates, safe image links) and every value is HTML-escaped before display.
